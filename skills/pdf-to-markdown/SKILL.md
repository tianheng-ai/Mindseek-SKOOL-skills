# pdf-to-markdown — 文件先轉成 Markdown 再讀

## 這支技能做什麼

PDF 直接丟給 AI，每一頁除了文字，還會被當成一張圖片再算一次用量。內容其實只是文字的文件，這一份圖片的用量是白花的。
這支技能在讀之前，先用微軟的免費工具 MarkItDown 把檔案轉成純文字的 Markdown，再讀轉好的那一份。

| 使用者說 | 你做什麼 |
|---|---|
| 給一個或多個 .pdf、.docx、.pptx、.xlsx，要你讀、整理、摘要、回答問題 | Step 1 → Step 5 |
| 「把這個資料夾的文件都轉成 Markdown」 | Step 1 → Step 4，每個檔都轉，最後給一張清單 |
| 「只轉、先不要讀」 | Step 1 → Step 4 |

## 鐵律（每一條都要做到）

1. **使用者不用打任何指令。** 安裝、轉檔都由你執行。不要叫使用者開終端機，也不要跟他要金鑰。
2. **原檔一個字都不動。** 不改名、不搬、不刪。轉好的檔案另外存。
3. **檔案留在使用者的電腦上。** 只用 MarkItDown 的基本轉檔，不接任何線上服務，不把檔案內容傳到別的地方。
4. **轉完一定檢查。** 轉出來幾乎是空的，就照 Step 4 改讀原檔，並跟使用者說原因。不准拿空白的結果硬答。
5. **說實話。** 轉好的文字一樣要算用量，省掉的是「每頁當圖片再算一次」那一份。不要說成完全不花用量。

## When NOT to Use

- **掃描檔、拍照存成的 PDF**：裡面沒有文字，轉出來是空的。直接讀原檔。
- **重點在圖表、照片、版面的文件**（設計稿、圖很多的簡報、要看圖回答的報告）：轉完圖會不見。直接讀原檔，或兩份都讀。
- **使用者要改的是原本那個 Word、簡報或試算表**：這支只負責讀，不負責改原檔。
- **只有一兩頁的短文件**：差別很小，直接讀就好。

遇到這些情況，跟使用者說一句為什麼這次不轉，然後直接讀原檔。

**不確定是不是上面這幾種，就先轉。** 轉檔前不用先查頁數或打開來看：照 Step 3 轉，交給 Step 4 的檢查判斷。只有使用者自己說了「這是掃描檔」「只有一頁」這類話，才在轉之前跳過。

## Step 1：確認 MarkItDown 能不能用

執行 `markitdown --version`。有版本號就跳到 Step 3。

## Step 2：沒有就自己裝（只需要裝一次）

先跟使用者說一句：「我先幫你裝微軟的免費轉檔工具 MarkItDown，裝一次就好，大約一兩分鐘。」然後照順序試，哪一個成功就停：

1. 電腦有 `uv`：`uv tool install "markitdown[all]"`
2. 電腦有 `pipx`：`pipx install "markitdown[all]"`
3. 有 Python 3.10 以上：`python3 -m pip install --user "markitdown[all]"`（Windows 用 `py -m pip install --user "markitdown[all]"`）

裝完再跑一次 `markitdown --version` 確認。指令找不到但剛剛顯示安裝成功，多半是安裝位置不在搜尋路徑裡：改用 `python3 -m markitdown`（Windows 用 `py -m markitdown`）代替後面所有的 `markitdown`。

三種都不行（通常是電腦沒有 Python，或公司電腦不准安裝）：

- 用白話告訴使用者：「這台電腦還沒有 Python，所以轉檔工具裝不起來。」
- 問他一次：要你幫忙裝 Python，還是這次先直接讀原檔。
- 他選直接讀，就照平常的方式讀原檔，不要卡在安裝上。

## Step 3：轉檔

- 在原檔所在的資料夾建一個子資料夾 `轉好的Markdown`（已經有就沿用）。
- 每個檔轉一次：`markitdown "<原檔完整路徑>" -o "<原檔資料夾>/轉好的Markdown/<原檔名>.md"`
- 輸出檔名保留原本的副檔名再加 `.md`（例如 `報價單.pdf.md`），同名的 Word 和 PDF 才不會互相蓋掉。
- 同名的 `.md` 已經存在、比原檔新、而且不是空的：不用重轉，直接用。
- 路徑一律用完整路徑，前後加引號（檔名常有空白和中文）。
- 一次很多檔：一個一個轉，某一個失敗就記下來繼續，不要整批停掉。

## Step 4：檢查轉出來的東西

每個轉好的檔做兩件事：看檔案大小，再讀開頭五十行。照下表處理：

| 看到什麼 | 代表什麼 | 怎麼做 |
|---|---|---|
| 幾乎是空的：檔案是 0 位元組，或扣掉空白、`NaN`、表格線之後剩不到兩百個字元，或內容只有頁碼、頁首頁尾這類重複的短字 | 內容是圖片（掃描檔，或每頁一張圖匯出的簡報） | 改讀原檔，跟使用者說「這份的內容是圖片，轉不出文字」。把那個空的 `.md` 刪掉，免得下次被當成轉好的拿來用 |
| 字都在，但標題變成一般文字 | PDF 常見，正常 | 照用。需要章節結構時自己從內容判斷，不要說文件沒有標題 |
| 表格裡一堆 `NaN` | 試算表的空格子 | 當成空白，不要當成資料 |
| 原檔有圖表，轉好的檔沒有 | 圖不會被轉出來 | 回答會用到圖表時，那幾頁改讀原檔 |
| 整份都是亂碼 | 檔案有加密或字型特殊 | 改讀原檔，跟使用者說一聲 |
| 只有幾段亂碼、碎字，或某張表不見 | 那幾頁的排版轉不好 | 回答用不到那幾段就照用；用得到，那幾頁改讀原檔 |

## Step 5：讀轉好的那一份，然後做使用者要的事

- 讀 `轉好的Markdown` 裡的檔，不再讀原檔（Step 4 判定要讀原檔的除外）。
- 回答裡引用內容時，說得出是哪一份文件。頁碼在轉檔後通常不準，不確定就不要寫頁碼。
- 做完在回覆最後加一小段：

```
已先轉成 Markdown 再讀：
轉好的檔案
- <完整路徑>
- <完整路徑>
改讀原檔的
- <檔名>：<原因>
```

每個檔一行。轉出來是空的、已經改讀原檔的，只列在「改讀原檔的」。沒有改讀原檔的就寫「無」。

## 常見狀況

| 狀況 | 做法 |
|---|---|
| 使用者把檔案直接拖進對話，沒有給路徑 | 拿得到檔案在電腦上的路徑就照做；拿不到就直接讀，並跟他說下次把檔案放進工作資料夾、給路徑，才轉得了 |
| 使用者問「省了多少」 | 只說看得到的事實：原檔幾頁、轉好的檔多少字。不要自己編省下的數字或百分比 |
| 轉檔跑很久 | 幾百頁的 PDF 可能要一兩分鐘，先跟使用者說一聲 |
| 之後同一份文件又被問到 | 直接讀已經轉好的那一份 |
