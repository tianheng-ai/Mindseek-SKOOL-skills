# handoff — 交接單

## 這支技能做什麼

對話一長，AI 會開始忘記前面的事；開新對話又要從頭講一遍。
這支技能在收工前把工作狀態寫成一張交接單，下一個對話貼一行就能接上。

兩種用法：

| 使用者說 | 你做什麼 |
|---|---|
| 「寫交接」「交接」「收工」「今天先到這」「換新對話」、`/handoff` | **寫交接**：Step 1 → Step 4 |
| 「讀 /…/交接單/….md」 | **接手**：照「接手」那一節做 |

## 鐵律（每一條都要做到）

1. **全自動，不問使用者問題。** 只寫這個對話裡看得到的事，不猜對話以外發生了什麼。
2. **不需要任何前置設定。** 不需要 git、GitHub、特定資料夾。任何一步拿不到資訊就跳過，**不要報錯停下**。
3. **只新增交接單，不動其他東西。** 不 commit、不切 branch、不改使用者原本的檔案。
4. **一定要有「下一步」**，而且是新對話可以直接照做的具體動作。
5. **路徑一律絕對路徑**，輸出前先確認檔案真的存在。

## When NOT to Use

- 只問了一個問題就結束的短對話
- 這次對話已經把事情全部做完、沒有後續
- 純閒聊

遇到這些情況，跟使用者說一句「這次不需要交接，事情已經做完了」就好。

## 寫交接

### Step 1：蒐集資訊（自動，不問使用者）

| 項目 | 怎麼拿 | 拿不到時 |
|---|---|---|
| 今天日期、現在時間 | Mac／Linux：`date +%Y-%m-%d` 和 `date +%H%M`；Windows PowerShell：`Get-Date -Format yyyy-MM-dd` 和 `Get-Date -Format HHmm` | 用你知道的今天日期，時間寫 `0000` |
| 目前工作資料夾 | `pwd`（Windows 用 `Get-Location`） | 見 Step 2 的「存放位置」 |
| 這次做了什麼 | 回顧這個對話 | — |
| 用到、改到的檔案 | 回顧這個對話裡讀過、寫過的檔案 | 沒有就刪掉「必讀檔案」一節 |
| git 狀態（可選） | 只有在 git 專案裡才跑 `git branch --show-current`、`git status -s`，**只讀不寫** | 不是 git 專案就直接跳過，不要提 |

### Step 2：寫交接檔

**存放位置**：`{目前工作資料夾}/交接單/{YYYY-MM-DD}-{HHMM}-{主題}.md`

- 放在目前工作資料夾裡，是因為 AI 在這裡一定有權限寫檔，不會跳出權限詢問或被擋。
- 沒有選工作資料夾（目前資料夾是家目錄或拿不到）時，改存到家目錄的 `交接單/`。
- 主題：英文小寫加連字號，≤ 30 字元，說明這次在做什麼（例如 `pitch-deck-draft`）
- `交接單/` 資料夾不存在就建立
- **同名檔案已經存在就在主題後加 `-2`、`-3`**，不要覆蓋舊的
- 用檔案工具寫，不要用 shell 指令拼檔案
- 寫入被擋（權限不足、沙盒限制）時，不要重試同一個位置：直接把整份交接單內容貼在回覆裡，請使用者自己存成檔案，並說明被擋的原因

**檔案格式**（用使用者在對話裡用的語言寫）：

```markdown
---
date: 2026-11-12
time: "18:30"
folder: /Users/<帳號>/Desktop/我的專案
topic: pitch-deck-draft
---

# {一句話：這次在做什麼}

## 完成
- 真的做完的事，一行一件

## 進行中
- 做到一半的事，寫清楚做到哪一步

## 下一步
1. 新對話第一件要做的事，具體到可以直接照做
2. ……

## 必讀檔案
- /絕對路徑/檔名 — 為什麼要讀這個檔

## 注意事項
- 踩過的坑、使用者說過的偏好或限制、還沒解決的問題
```

**寫法規則**：

| 規則 | ✅ 這樣寫 | ❌ 不要這樣寫 |
|---|---|---|
| 具體 | 「提案第 3 節市場規模寫完，第 4 節競品還沒開始」 | 「繼續寫提案」 |
| 完成和進行中分清楚 | 做一半的放「進行中」，寫到哪一步 | 把做一半的事寫成完成 |
| 精簡 | 「完成」≤ 10 行，細節指向必讀檔案 | 把對話過程寫成流水帳 |
| 必讀檔案附理由 | 「…/budget.xlsx — 第 2 頁的數字是最新版」 | 只列一串路徑 |
| 記下使用者的偏好 | 「使用者要繁體中文、語氣口語」 | 讓新對話重新問一次 |

沒有內容的段落（例如沒有「注意事項」）**直接刪掉**，不要留空標題。

### Step 3：檢查路徑

寫完後逐一確認：

1. 交接檔本身存在（讀一次，或 `ls`）
2. 「必讀檔案」裡每一條路徑都存在；不存在的就刪掉或改正。**沒讀過、只在對話裡聽說的檔案尤其要確認**

路徑寫錯一個字，新對話第一步就找不到檔，等於交接失敗。

### Step 4：回報

**只輸出這三行**，不要重述交接檔的內容：

```
交接單已存：{交接檔的絕對路徑}
接下來請開一個新對話（同一個資料夾），貼上下面這行：
讀 {交接檔的絕對路徑}
```

### 寫完之後

- **寫完交接就停手。** 使用者如果還在這個舊對話裡要你繼續改東西，先提醒一句：「已經寫了交接，繼續在這裡做的話交接單會過期，要我做完後更新交接單嗎？」
- 使用者要你繼續做，做完後**更新同一份交接檔**的「完成」「進行中」「下一步」，再輸出一次 Step 4 的三行。

## 接手

使用者貼上「讀 {路徑}」時：

1. 讀交接檔。讀不到就說「找不到這份交接單」，請使用者確認路徑，或到工作資料夾的 `交接單/` 找最新的一份。
2. 讀「必讀檔案」裡列的檔案。
3. 用三行回報：這次要做什麼、目前做到哪、你準備先做哪一步。
4. 接著直接做「下一步」第 1 項。下一步會刪檔、覆蓋檔案、寄信或付費這類收不回來的事，先問使用者再做。

## 常見錯誤

| 錯誤 | 為什麼不行 | 改法 |
|---|---|---|
| 不是 git 專案就報錯停下 | 大部分人的工作根本不在 git 專案裡 | git 那步直接跳過 |
| 在使用者的專案裡 commit | 使用者沒要求，會弄亂他的專案 | 只新增 `交接單/` 裡的檔 |
| 把交接單寫到工作資料夾以外 | 會跳權限詢問，有些 AI 直接擋下來 | 寫在工作資料夾的 `交接單/` |
| 問使用者「這次做了什麼」 | 使用者就是不想再講一次才用這支技能 | 自己回顧對話 |
| 缺「下一步」 | 新對話不知道從哪開始 | 必填，寫具體動作 |
| 起始那行用相對路徑 | 新對話在別的資料夾就找不到 | 一律絕對路徑 |
| 必讀檔案路徑憑印象寫 | 少一層資料夾就找不到 | Step 3 逐條確認 |
| 同名檔案直接覆蓋 | 早上的交接被下午的蓋掉 | 加 `-2` |
| 回報時把交接內容整份貼出來 | 浪費篇幅，新對話讀檔就有 | 只輸出三行 |
